# Plugin decisions

Rule: install a plugin only when core WordPress plus a small amount of theme code can't meet the requirement well. Overlapping plugins are not allowed. Every entry records its purpose, the alternatives considered and its configuration.

| Plugin | Status | Purpose | Why core/theme isn't enough | Alternatives considered | Configuration notes |
|---|---|---|---|---|---|
| **TechDoseDaily Core** (first-party, `plugins/techdosedaily-core`) | **Built (Phase 1b)** | Publication data model: sections/URLs, story types, topics, editorial meta, placements, view counts, newsletter adapter, form security, schema ownership | This data must survive any future theme change, so it can't live in the theme | Keeping it in the theme's `inc/` (rejected: data lost on redesign) | Activate before the theme. Uninstall keeps data. See its README for the data model and the ownership table. |
| **Yoast SEO (free)** | **Decided (Phase 6)**; verified locally with 28.6; install on staging | Titles, meta descriptions, canonicals, robots output, Open Graph/X cards, XML sitemaps. JSON-LD only when chosen as schema owner. | Core sitemaps lack per-type control, meta descriptions and OG tags; rebuilding Yoast's editor UI isn't worth it | Rank Math (more features, heavier UI); The SEO Framework (lighter, fewer editor controls) | Ownership and switching: `SEO-SCHEMA.md`. Site settings → Structured data picks one graph (Core or Yoast); Core turns Yoast JSON-LD off through `wpseo_json_ld_output` and falls back to its own graph if Yoast is missing. Core supplies only a fallback description (deck/intro), noindex rules and sitemap exclusions through Yoast filters. Breadcrumbs off; attachment URLs redirected; tags, formats and date archives off. Google News sitemap: not built (separate launch decision). |
| **MailPoet** | Decided | Newsletter subscribers, lists, sending, Daily Tech Brief email. Used only through Core's `Provider` adapter | Core has no mailing-list or newsletter tooling | Mailchimp, Brevo, Kit, Beehiiv (hosted). Kept reachable through the theme's provider adapter. | The front-end form is our markup posting to `/wp-json/tdd/v1/subscribe`. Core resolves the provider (`MailPoet_Provider` implements `TDD\Core\Newsletter\Provider`), so templates never know which provider is used. Set the list ID in option `tdd_newsletter_mailpoet_list` (settings UI in Phase 4). Double opt-in is still **open**. Check the current free-tier limit and choose a sending service. |
| **LiteSpeed Cache** | Recommended for staging (Phase 7, free plugin; no QUIC.cloud services needed) | Page cache + browser cache on Hostinger's LiteSpeed server | Server-level cache that integrates with the host; TechDoseDaily Core drives it through its API (per-page TTL to the next editorial change, no-cache rules, purge on editorial changes) | WP Super Cache / W3TC (not LiteSpeed-native) | Settings in `PERFORMANCE.md` §3.4: logged-in cache, lazy load, minify/combine, critical CSS, guest mode and image optimisation **off** (the theme already does these correctly); `/contact/`, `tdd_nl`, `tdd_cf` excluded. Correctness never depends on it: without a page cache the site sends the same headers. |
| **Redirection** | Proposed (pre-launch) | 301s for changed URLs, 404 log | Core has no redirect manager | Yoast Premium redirects (paid); server rules (less editor-friendly) | Monitor 404s weekly after launch. Never redirect all 404s to home. |
| Forms plugin | **Not used** | Contact and newsletter forms | Approved markup and states (error summary, field errors, success) need exact HTML; plugin forms would need restyling or overriding | Fluent Forms, Gravity Forms, WPForms | TechDoseDaily Core module with REST endpoints, nonces, honeypot, time-trap and rate limiting (Phase 4). |
| Security plugin | Deferred | Login hardening, firewall | Hostinger's own malware scanner, firewall and 2FA may be enough | Wordfence (free) if needed | Decide at staging after reviewing what the Hostinger plan includes. |
| Analytics | **Open** | GA4 or a privacy-friendly alternative | — | Site Kit (Google), a manual GA4 tag with Consent Mode v2, Plausible/Matomo | Events: newsletter_subscribe, contact_submit, search, outbound source click, related-story click. |

Not allowed: page builders (Elementor, Divi, WPBakery, Avada), multipurpose or magazine themes, slider, social-share or related-posts plugins, and anything that loads jQuery or third-party trackers on the front end.
